# MusCos 機能仕様

機能の詳細仕様と、実装上の懸念点・対策をまとめた資料。概要は [README.md](../README.md) を参照。

---

## 1. 音階当てクイズ

### 流れ
1. モードを選ぶ
2. 「開始」ボタンを押す（真鍮色の大きな横長ボタン。Enter キーでも開始）
3. ランダムに選ばれた音が鳴る。開始後は「開始」が「もう一度聴く」「次の問題」の2つのボタンに切り替わる
4. 画面のピアノ鍵盤から答えの鍵盤を押す
5. 正解 / 不正解を表示（不正解のときは正解の鍵盤もハイライト）
6. 次の問題へ（設定を変えると「開始」に戻る）

### モード

| モード | 出題範囲 | 対象の鍵盤 | 候補数 | 当てるもの |
|---|---|---|---|---|
| 簡単 | C4〜B4 | 白鍵のみ | 7音 | 音名 |
| 難関 | C3〜B5 | 白鍵のみ | 21音 | 音名＋オクターブ |
| 発展 | C4〜B4 | 白鍵＋黒鍵 | 12音 | 音名（♯/♭を含む） |
| 連続 | 上記いずれかの範囲 | 選んだモードに従う | — | 2〜5音の並びを順番どおり |

- 音名は国際式（C4 = 中央のド）。表記は「ドレミ」「CDE」切り替え可能にする
- 黒鍵の表記は C♯/D♭ の両方を表示

### 連続モード
- 出題範囲（簡単 / 難関 / 発展）と音の個数（2〜5）を選んで開始
- 選んだ個数の音が一定間隔で続けて鳴る
- 鳴った順番どおりに鍵盤を押して答える。1音ごとに正誤を表示し、全音正解でその問題を正解とする
- 「もう一度聴く」で並び全体を再生し直す

### 鍵盤UI
- 鍵盤は画面上でピアノの見た目にする（白鍵・黒鍵の位置関係を正しく）
- 鍵盤は出題パネルから独立させ、**画面の下に固定**する（スクロールしても常に見える）。高さは PC 210px（画面の高さが720px以下なら160px）、スマホ 170px
- 簡単・発展：1オクターブの鍵盤を画面幅いっぱいに表示
- 難関：PC では3オクターブ（C3〜B5）の鍵盤を表示。スマホ（幅760px以下）では「1オクターブの鍵盤で音名を選ぶ → 3〜5のボタンでオクターブを選ぶ」の2段階入力（オクターブのボタンは鍵盤のすぐ上）
- PCではキーボード操作も可能（A S D F G H J = ド〜シ、W E T Y U = 黒鍵。難関は続けて 3〜5 でオクターブ。R = もう一度聴く、Enter = 開始・次へ）。ボタンには対応するキーを表示する（スマホでは表示しない）
- 出題中以外に鍵盤を押すと、その音が鳴る（試し弾き）
- 設定は PC では左の列に常に表示し、スマホでは1行にたたむ（押すと開く）

### 記録
- 正解数 / 出題数、連続正解数をモード別に `localStorage` に保存

## 2. リズムゲーム

### 画面構成
- **1行 = 1小節（4/4拍子）**。1小節を4つのブロック（＝1拍ずつ）に分けて横に並べる
- それを **4行（4小節分）** 表示する（将来は行数を増やす）
- 各ブロックにはその拍のリズム（音符・休符）を表示

```
| ♪.♬ | ♪.♬ | 3連 | 3連 |   ← 1小節目
| ♫   | ♩   | ♬♬  | 𝄽   |   ← 2小節目
| ...                    |   ← 3小節目
| ...                    |   ← 4小節目
```

### サンプルパターン（1小節の例）
以下は一例。これ以外にも多数のパターンを用意する。

| 拍 | リズム | 長さ |
|---|---|---|
| 1拍目 | 付点8分音符＋16分音符 | 0.75拍＋0.25拍 |
| 2拍目 | 付点8分音符＋16分音符 | 0.75拍＋0.25拍 |
| 3拍目 | 8分音符の3連符 | 0.333拍×3（1拍を均等に3分割） |
| 4拍目 | 8分音符の3連符 | 0.333拍×3（1拍を均等に3分割） |

### 遊び方
1. BPM を設定（60〜180、スライダー＋数値入力）
2. 開始すると1小節分のカウントイン（メトロノーム音）
3. 今の拍のブロックが真鍮色に光り、ブロックの中を赤い縦線（再生位置）が進む。次に叩く音符を赤くする表示はしない（混乱するため廃止）
4. ユーザーは叩くボタンをタップ／クリック、または PC のスペース・F・J キーで叩く
5. 叩いた音符にエフェクトを出し、文字の判定（ぴったり／おしい（早い・遅い））も表示する
6. 4小節終了後に結果（正確さ、平均のズレ ms、早い/遅い傾向）を表示

- 休符中の打鍵は減点しない（判定対象外）

### 叩いたときのエフェクト
文字を見なくても判定が分かるように、音符そのものに出す。

| 判定 | エフェクト |
|---|---|
| ぴったり | 音符が大きく弾み、太い二重の輪が広がる |
| おしい | 音符が少し弾み、点線の輪が広がる。音符の下に早い（◀）／遅い（▶）の矢印が残る |
| ミス | 音符が赤く薄くなり、小さく揺れる |

- 輪と矢印は音符の SVG の中に描く（画面の大きさが変わってもずれない）
- 動きを減らす設定（prefers-reduced-motion）のときは、弾み・輪・揺れを出さず、色と矢印だけにする

### 画面の配置と操作
- PC：音符の4行を左、縦長の叩くボタンを右に並べ、画面の高さに収める。音符のすぐ上に「開始」「やめる」「別のリズムにする」の操作ボタンを置く
- スマホ（幅760px以下）：操作ボタンと叩くボタンを画面の下に固定する。設定は1行にたたむ（押すと開く）
- キー操作

| キー | 動き |
|---|---|
| Space / F / J | 叩く |
| Enter | 開始（演奏していないとき） |
| Esc | やめる（演奏中・補正中） |
| N | 別のリズムにする（演奏していないとき） |

### 使用する音符（1拍＝1ブロック内に収まるもの）

| 種類 | 1ブロック内の打数 | 初期実装 |
|---|---|---|
| 4分音符 | 1 | ○ |
| 4分休符 | 0 | ○ |
| 8分音符×2 | 2 | ○ |
| 8分音符＋8分休符 / 8分休符＋8分音符（裏拍） | 1 | ○ |
| 16分音符×4 | 4 | ○ |
| 8分＋16分×2 / 16分×2＋8分 | 3 | ○ |
| 付点8分＋16分 / 16分＋付点8分 | 2 | ○ |
| 8分音符の3連符 | 3 | ○ |
| 16分休符を含む形（シンコペーション） | 1〜3 | 後で |
| 2分音符・付点4分・4分3連符（ブロックをまたぐ） | — | 後で（ブロック設計の拡張が必要） |

- 難易度に応じて使う音符を絞る（初級：4分・8分・休符 / 中級：16分・付点 / 上級：3連符。シンコペーションは後で追加）
- 難しさの選択肢には「例題（付点と3連符）」もあり、上のサンプルパターンを4小節分出題する
- 「お手本の音を鳴らす」をオンにすると、叩くタイミングで短い音が鳴る（初期状態はオン）

### 内部データ形式
- 1拍を **12tick** に分割して音符位置を整数で持つ（16分 = 3tick、3連8分 = 4tick の両方を割り切れる）
- 例：`{ measure: 0, beat: 1, ticks: [0, 6] }` = 2拍目に8分音符×2
- 例：サンプルパターンの1拍目（付点8分＋16分）= `ticks: [0, 9]`、3拍目（3連符）= `ticks: [0, 4, 8]`
- 将来の「音楽読み込み」「楽譜から作成」もこの形式に変換して流用する

## 3. 懸念点と対策

### 音まわり
| 懸念 | 内容 | 対策 |
|---|---|---|
| ブラウザの自動再生制限 | ユーザー操作前は音が鳴らない。iOS はマナーモードで Web Audio が無音になることがある | 「開始」ボタン押下時に AudioContext を開始／再開し、初回に「音が出ます（マナーモードは解除してください）」と案内する |
| 音色 | オシレーターの音は電子音っぽく、低音・高音で音程が判別しにくい | Tone.js の Sampler で Salamander Grand Piano のサンプル（A2〜C7、短3度おき）を CDN から読み込み、間は音程をずらして補完。読み込めないときは合成音に切り替える |
| 音域 | 極端な低音・高音はスマホのスピーカーで判別しにくい | 難関モードを C3〜B5 に限定して対応 |

### 鍵盤UI
| 懸念 | 内容 | 対策 |
|---|---|---|
| 難関モードの鍵盤数 | 3オクターブ（白鍵21個）はスマホ幅では押しにくい | スマホでは「音名を選ぶ → オクターブを選ぶ」の2段階入力 |
| 連続モードの入力ミス | 押し間違えたときに並び全体が不正解になる | 1音ずつ正誤を表示し、どこで間違えたか分かるようにする |

### リズムゲーム
| 懸念 | 内容 | 対策 |
|---|---|---|
| タイミング精度 | `setTimeout` や画面描画のタイマーは数十ms ずれる | 音ゲーと同様に**音の再生時刻をマスター時計**にする。時刻はすべて `AudioContext.currentTime` 基準で管理し、少し先の音を予約再生（先読みスケジューラ）。ハイライトは `requestAnimationFrame` で現在時刻から計算して描画 |
| 入力の時刻 | 描画フレーム単位で判定すると最大1フレーム（約16ms）ずれる | 判定は描画と切り離し、入力イベントの `event.timeStamp` をオーディオ時刻に変換して判定（`getOutputTimestamp()` で対応付け）。入力は `click` ではなく `pointerdown` / `keydown` を使う |
| 出力の遅延 | Bluetoothイヤホンは100〜300ms遅れる。端末ごとに遅延が違う | `latencyHint: 'interactive'` で低遅延出力を指定し、`outputLatency` / `baseLatency` を補正。加えて**キャリブレーション機能**（メトロノームに合わせて数回叩き、平均のズレを補正値として保存） |
| ズレの見える化 | 早い/遅いの傾向が分からないと補正しにくい | 結果画面と演奏中にヒットエラーメーター（打鍵ごとのズレを線で表示）を出す |
| 判定幅 | BPM180の16分音符は約83ms間隔で、判定幅が広いと隣の音符と重なる | 判定幅をBPMと音符間隔に応じて可変にする（例：Perfect ±40ms、Good ±80ms を上限に、音符間隔の半分以下に制限） |
| 「1ブロック＝1拍」の制約 | 2分音符・付点4分・4分3連符などブロックをまたぐ音符が表せない | 初期は1拍内で完結する音符に限定。内部データは tick 単位にしておき、後で表示だけ拡張できるようにする |
| ハイライトの粒度 | ブロック単位だと16分音符のどれを叩くか分かりにくい | ブロックのハイライト＋ブロック内を動く縦線（再生位置カーソル）の2段構え。次に叩く音符を赤くする強調は、かえって混乱するため廃止 |
| 音符の描画 | 音符・連桁・3連符の「3」を描く必要がある | パターン数が限られるため、1拍分の SVG を自前で描画（js/notation.js）。VexFlow は使わない |

### デザイン
| 懸念 | 内容 | 対策 |
|---|---|---|
| 「AIっぽくない」の基準が主観的 | 作ってみないと合意が取りにくい | デザイン候補PDFから方向性を選び、先に見た目だけのモックで確認 |
| 日本語Webフォントが重い | 明朝体などは数MBになる | Google Fonts の分割配信を利用、見出しだけWebフォントにする |

### 将来機能
| 懸念 | 内容 | 対策 |
|---|---|---|
| 音楽読み込み | 単音の音程検出はブラウザ内で可能だが、和音・伴奏入り音源からの抽出は重い | 単音はブラウザ内、伴奏入り音源の解析はサーバ側で処理する方向で検討 |
| 楽譜から作成 | 画像の楽譜を読み取る（OMR）はブラウザだけでは困難 | MusicXML / MIDI はブラウザ内で解析、画像の楽譜はサーバ側で処理する方向で検討 |
